# Docusaurus to Leed

How a Docusaurus site (v3, classic preset) maps onto a Leed documentation set. Read it with `../SKILL.md`, which owns the order of the steps; this file owns what each Docusaurus construct becomes.

## Layout and config

| File | Holds |
|---|---|
| `docusaurus.config.js` or `.ts` | site `url` and `baseUrl`, the docs plugin options (`path`, `routeBasePath`, default `docs`), `themeConfig.navbar`, `themeConfig.footer`, `themeConfig.colorMode`, the `customCss` path, plugins (redirects) |
| `sidebars.js` or `.ts` | one or more named sidebars; each item is a doc id, a `category`, a `link`, or `{type: 'autogenerated', dirName}` |
| `docs/` | the pages, `.md` or `.mdx`; folders may hold `_category_.json` or `_category_.yml` |
| `static/` | files served from the site root (`static/img/x.png` is `/img/x.png`) |
| `src/css/custom.css` | Infima variable overrides |
| `src/pages/` | stand-alone React or Markdown pages outside the docs; not migrated, listed in the report |
| `versioned_docs/`, `versioned_sidebars/`, `i18n/` | older versions and translations |

A doc's id is its path under `docs/` without the extension and without number prefixes (`01-intro.md` is `intro`), unless front matter sets `id`. Its URL is `<baseUrl><routeBasePath>/<id or slug>`.

## Navigation to menus

- **Explicit sidebar.** Walk the sidebar named in `sidebars.js` in order. A `category` becomes a folder named by its `label`; a doc id becomes a page; a `link` item (external URL) cannot be a docs-menu page, so report it, or add it to the top menu when the user wants it. When several sidebars exist, each usually matches a navbar `docSidebar` item: migrate them as top-level folders of one docs set in navbar order, unless the user wants separate sets.
- **Autogenerated sidebar.** Order is `sidebar_position` front matter, then `_category_.json` `position`, then number prefixes, then alphabetical. Labels come from `sidebar_label`, then `title`, then the first heading; a folder's label from `_category_.json` `label`.
- **Category links.** A category with `link: {type: 'doc', id}`, or a folder holding `index.md`, `README.md` or a doc named after the folder, has a landing page. Leed folders cannot be links: make that page the first page in the folder and alias the category URL to it. A `link: {type: 'generated-index'}` page is a generated list of the children: drop it (the Leed menu already lists them), alias its URL to the first child, and report it.
- `sidebar_class_name`, `sidebar_custom_props`, `collapsible` and `collapsed` have no menu equivalent; report them only if the user relies on them.

## Header and footer

- `themeConfig.navbar.items` become the **top** menu, in order, left items before right. `doc` and `docSidebar` items link to the migrated page (`pageid:`); `to` and `href` links keep their target (`pageid:` when it is a migrated page); a `dropdown` becomes an item with children. `search`, `localeDropdown` and `docsVersionDropdown` are not menu items: Leed's docs header renders its own search, and the rest go in the report.
- `themeConfig.navbar.logo` and `title`: point the user at Settings, General, for the docs logos; do not upload a logo into the menu.
- `themeConfig.footer.links` become the **bottom** menu: in the multi-column form each column `title` is a parent item and its `items` its children; in the simple form the links are top-level items. An `html` item and `copyright` are not menu items: report them.

## Markdown dialect

| Source | Leed | Notes |
|---|---|---|
| `:::note`, `:::tip`, `:::info`, `:::warning`, `:::danger` | `:::note`, `:::tip`, `:::info`, `:::warning`, `:::danger` | Same keyword, same closing `:::` |
| `:::caution` | `:::warning` | Leed has no caution type |
| `:::note[Title]` or `:::note Title` | `:::note Title` | The title moves out of the brackets; Markdown in a title becomes plain text |
| Nested admonitions with `::::` | `::::tip` around `:::info` | Leed nests the same way, outer block with more colons |
| Custom admonition keywords from `admonitions.keywords` | `:::note` | Approximated; report the keyword |
| `> [!NOTE]` and other GitHub alerts (via a remark plugin only) | `:::note` | `[!IMPORTANT]` to `:::info`, `[!CAUTION]` to `:::danger` |
| `<Tabs>` with `<TabItem value label>` | `===tabs-container` with `@tab <label>` | One `@tab` per `TabItem`, label from `label`, then `value`; close with `===` |
| `<Tabs groupId="os">` | `===tabs-container {data-tabs-groupId="os"}` | Synced tab groups keep their group id |
| `<TabItem default>`, `queryString`, `lazy` | `@tab` | Dropped; the first tab is the default |
| `<details><summary>Title</summary>` | `+++ Title` | Closed collapsible; `<details open>` becomes `++> Title` |
| Fenced code with a language | fenced code with the same language | |
| `title="file.js"` in the fence meta | fenced code | Approximated: the title becomes the sentence before the block |
| `{1,4-6}`, `// highlight-next-line`, `showLineNumbers` | fenced code | Dropped: delete the magic comments from the code |
| a `jsx live` fence | fenced code `jsx` | Approximated: live playgrounds do not run in Leed |
| `npm2yarn` fences | `===tabs-container` with `@tab npm` and `@tab yarn` | Write each package-manager variant as its own tab |
| a `mermaid` fence | a `mermaid` fence | Same; Leed renders Mermaid |
| `$...$`, `$$...$$` (KaTeX plugin) | inline math and a `math` fence | Leed writes inline math in double backticks starting `math`, and block math as a fence whose language is `math` |
| `import X from '@site/...'` and `<X />` components | nothing | MDX imports are removed; each component is converted from its markup by hand or reported |
| `<iframe src>` or a YouTube `<iframe>` | `{% iframe src="..." %}` or `{% youtube videoId="..." %}` | |
| `<head>`, `<Highlight>`, `<BrowserWindow>`, `<DocCardList />` | nothing | Dropped; `<DocCardList />` lists child pages the menu already shows. Report each |
| `{#custom-id}` on a heading | heading | Dropped: Leed headings take their generated slug. Fix links to the old anchor |
| `[[toc]]`-like `<TOCInline />` | nothing | Leed's docs layout renders its own table of contents |
| `<!-- truncate -->` and other HTML comments | nothing | Stripped on import |

## Includes and reusable content

Docusaurus partials are `.md` or `.mdx` files whose names start with `_` (not rendered as pages), imported into a page with `import Part from './_part.mdx'` and placed with `<Part />`. Inline the partial's content where `<Part />` stands, converting it with the same table, and list each in the report with the pages that now hold a copy. Props passed to a partial (`<Part name="x" />`) are substituted by hand.

## Frontmatter to page fields

| Docusaurus | Leed |
|---|---|
| `title` | the page title; a leading `#` heading is removed from the body (SKILL.md step 4) |
| `sidebar_label` | the menu entry's name, set in the staged `menu.json` |
| `sidebar_position` | the order in the menu |
| `description` | `summary` |
| `keywords`, `tags` | dropped by the bulk import, which stores only `title` and `summary`; report each page's values so the user can set them as keywords or labels in the CMS |
| `id`, `slug` | not stored: they make the old URL, which becomes a path alias |
| `image` | dropped (a social card image); report it |
| `draft: true`, `unlisted: true` | not migrated by default; ask, and report |
| `hide_title`, `hide_table_of_contents`, `toc_*`, `pagination_*`, `custom_edit_url`, `last_update`, `displayed_sidebar`, `parse_number_prefixes` | dropped; report each |

## Assets

Images live in `static/` (referenced as `/img/x.png` or `@site/static/img/x.png`) or beside the page (`./img/x.png`, `require('./x.png').default`). Resolve every reference to its file in the copy, upload it with `leed asset upload`, and write the returned markdown in its place. A Docusaurus image with `title` keeps it as a Leed caption. Downloadable files linked with `pathname:///` or `/files/...` are uploaded as documents.

## Redirects and old URLs

- Every page's old URL: `<routeBasePath>/<slug or id>`, with the site `baseUrl` in front, with or without a trailing slash as `trailingSlash` says. Alias each to its page.
- `@docusaurus/plugin-client-redirects`: each `redirects[]` entry's `from` paths become aliases of the page at `to`. `createRedirects` is code: read it, list the old paths it produces for the migrated pages, and alias those; report it if it cannot be evaluated by reading.
- A `to` outside the docs (an external URL, a blog page) cannot be an alias: report it.

## Theme

The brand color is `--ifm-color-primary` in `src/css/custom.css` (with `-dark`, `-darker`, `-darkest`, `-light`, `-lighter`, `-lightest` shades), and a `[data-theme='dark']` block may override it. When tailoring is allowed, map `--ifm-color-primary` to the brand accent token and its darker shade to the hover token; otherwise choose the nearest built-in `color-theme-*`. Infima's other variables, the navbar and footer styles and any swizzled theme components are not migrated: report swizzled components (`src/theme/`) by name.

## Known gaps

- Code block titles, line highlighting, line numbers and live code blocks.
- React components and MDX imports with no Markdown equivalent, swizzled theme components and `src/pages/` pages.
- `generated-index` category pages and `<DocCardList />`.
- Custom heading ids (`{#custom-id}`) and links to them.
- Versioned docs (`versioned_docs/`) and translations (`i18n/`): only the current version and default locale migrate.
- Sidebar `link` items, `html` navbar and footer items, the footer copyright, and the version and locale dropdowns.
- `createRedirects` rules that cannot be read as fixed paths, and redirects to non-docs targets.
- `draft` and `unlisted` pages, unless the user asks for them.
